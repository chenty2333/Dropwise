# Offline discovery: synchronous transaction interruption and field-level judgment

This directory is the round-5 offline-discovery package.  It has two results
that support each other:

1. **A mechanism result on synchronous psycopg 3.3.6.**  One asynchronous
   exception at transaction entry/exit can produce four states: an advanced
   local counter with an idle server (D), an unread reply (C), an open server
   transaction with a local counter (B), and an open server transaction with no
   local owner (S4).  B and S4 silently lose the next transaction's write; D is
   invisible to `info.transaction_status` and is reused by `psycopg_pool` across
   checkouts; C is loud but unusable.  A candidate repair fixes B, S4 and D,
   fails C closed, and keeps the pool safe.

2. **A method result.**  `dropwise_py/fields.py` replaces the single-blob M1
   observation with per-field `EFFECT`/`STATE` contracts, per-field
   expectations and an explicit coverage statement.  It is used unchanged on
   the async engine and on the synchronous signal harness.

Both are offline: a disposable local PostgreSQL container, no upstream contact,
no production service, no host network change.

## Quick start

```sh
bash run-sync.sh                 # throwaway postgres, all experiments, fresh logs
# or, against an existing disposable database:
cd python && python -m pgsync.case --port <pg-port> --log-dir /tmp/dwod points
```

The runner checks the pinned psycopg source lines, runs the no-service tests,
the timing sweep, the original/fix phase matrices, the pool tests, the real
`SIGINT` check, the legitimate-vs-abandoned contrast, and the field replay, then
writes `SUMMARY.md`.  It requires `docker` and the Python environment named by
`$PYTHON` (default `~/dropwise-py-work-r3/venv313/bin/python`; psycopg 3.3.6,
psycopg_pool 3.3.3).

A committed run is in [`logs/2026-10-22/`](logs/2026-10-22/) (raw JSONL without
the large frame logs; the frame logs are regenerated by the runner).

## Results at a glance

| interrupt point | original | fix |
|---|---|---|
| entry wait (B) | retry/survivor `ok`, observer sees nothing: silent-loss 3/3 | clean, visible 3/3 |
| entry pre-send (D) | next `transaction()` bare `AssertionError`; server IDLE | clean, visible 3/3 |
| entry after send (C) | `another command is already in progress`; only close recovers | closed (fail-closed) |
| exit pre-commit (S4) | retry/survivor `ok`, invisible: silent-loss 3/3 | clean, visible 3/3 |
| body | correct 3/3 | correct 3/3 |
| exit wait | commit applied, exception; ambiguous Post 3/3 | unchanged 3/3 |

Pool (one connection, original): B is discarded by the pool's reset, D is
**reused** 3/3 across checkouts; the next transaction raises the bare assertion
and the next write is not committed.  With the fix, B and D are both repaired
and the same backend is safely reused 3/3.

Real-signal sweep (60 trials, 2–500 µs): 21 clean, 12 D, 9 C, 18 B; every
non-clean trial lost the survivor write.  A real `SIGINT` reproduced B 3/3.
Exact windows are host-specific; the state classes are the result.

Field contract on the same sync trials: `target.visible` is Pre (allowed),
`successor.visible` and `client.clean` are violations in B/S4/D; `server.clean`
holds in D and fails in B/S4 — the per-field split that the pool's
`transaction_status` check misses.

## Evidence labels

* **Observed**: rows read by the independent observer, client/server state
  captured in the trial, wire frames, real-signal sweep counts.
* **Source interpretation**: why a state arises (pinned lines, `_num_transactions`
  guards, savepoint nesting).  Pinned by `pgsync.case points`.
* **Fault injection**: `sys.settrace` at a source line; used to construct a
  state exactly.  Real reachability of the same state is shown separately by
  the sweep.
* **Candidate repair**: a runtime monkeypatch, not an upstream patch; its
  behaviour is measured, not assumed.
* **Hypothesis / next**: the upstream patch, the ownership witness, the kernel
  observer, and the Rust field port are proposals, not results.

## What is not claimed

* Not a security vulnerability report; the maintainers have declined to
  document a contract for signal-time interruptions (#1293).
* Not a production probability: 60 sweep trials and 3 trials/cell are existence
  and consequence measurements on one host.
* Not an exhaustive psycopg model: async, pipelines, `force_rollback`, nested
  entry and two-phase transactions are outside this round's fix matrix.
* Not a claim that every pool use loses a write: the victim can fail loudly at
  commit; the finding is that an unrelated next checkout receives the handle
  and the failure is far from the interrupted entry.
* Not a kernel/eBPF result: §4.6 of the mechanism report explains why wire and
  server state alone cannot distinguish legitimate nesting from an abandoned
  outer transaction; an ownership witness is still needed.
